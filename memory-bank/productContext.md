# productContext — 사용자가 겪는 흐름과 지켜야 할 경험 (계획서 4.1 (1))

## 사용자
- **어르신**: 핵심 이용자. 돌봄 대상이 아니라 스스로 선택하고 즐기는 능동적 이용자로 본다.
- **보호자**: 어르신이 동의한 범위만 보고, 그걸 가족 간 대화 소재로 쓴다.

## 서비스 이용 흐름 (앱 화면 1~15)
**처음 한 번 (1~5)**
모드 선택 → 어르신은 **이름만** 입력하고 시작 → 앱에 6자리 연결 코드 표시 → 보호자가 코드 입력해 연결 → 어르신이 공유 항목을 직접 고름 (**모든 항목 기본값 '공유 안 함'**, 건강 항목은 따로 구분해 안내)

**매일 (6~12)**
- 하루 1번 대화 알림, 또는 어르신이 원할 때 앱을 열면 AI가 **지난 기억으로 먼저 인사**
- 대화 상태 표시: 'AI가 말하는 중 → 말씀을 듣는 중 → 답변 확인 중'
- 못 알아들으면 다시 묻거나 글자 입력으로 대신
- AI는 흐름이 맞을 때 회상 놀이·관심사 퀴즈를 **제안만** 하고, 어르신이 원할 때만 진행
- 일상 확인 질문은 **하루 1번만**. 놀이를 거절·중단해도 대화는 그대로 이어짐

**언제든 (13)**: AI가 기억하는 내용과 그 **출처가 된 대화**를 직접 보고 지울 수 있음

**보호자 (14~15)**: 동의한 항목의 날짜별 일상 요약 + 놀이 참여 현황만. 이야기가 없던 항목은 "오늘은 이야기가 없었어요". 의학적 판단 없음

## 꼭 지킬 경험 (어기면 계획서 위반)
- 알림은 하루 1번. 응답 안 해도 **반복 알림 없음, 보호자에게 경고 없음** (감시 방지)
- 놀이는 강요하지 않음. 중단은 오답이 아님
- AI가 만든 부정확한 정보가 보호자에게 사실처럼 가지 않음
- 고령자 친화 화면 (참고: 계획서 [15] 고령자 모바일 앱 설계 가이드라인)

## 앱 쪽 예외 처리 (계획서 4.2, 강현준)
마이크 권한 거부 → 필요성 안내 + 설정 화면 이동 · 음성 인식 실패 → 재입력 안내 + 텍스트 입력 ·
어르신 무응답 → 잠시 후 한 번 다시 안내, 그래도 없으면 대화 화면 종료 · 서버 지연 → 로딩 표시, 타임아웃·재시도 ·
알림 권한 거부 → 설정 안내 + 앱 안 알림 확인 · 기억 삭제 실패 → 오류 표시 + 재시도 · 앱 비정상 종료 → 오류 로그 + 상태 복구 ·
퀴즈 수신 실패 → 기본 퀴즈 또는 재시도 · 중복 알림 → 알림 ID로 거름 · 인터넷 끊김 → 오류 안내 + 재시도
