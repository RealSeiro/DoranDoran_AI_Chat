# systemPatterns — 구조와 결정 (계획서 4장 기준)

## 전체 구조
```
[Android 앱]  ──HTTP API (Bearer 토큰)──▶  [FastAPI 서버]  ──함수 호출──▶  [AI 모듈 server/ai/]
 Kotlin, Compose                              │  app/service.py 대화 엔진        respond()
 어르신 모드 / 보호자 모드                     │  app/rules.py   서버 규칙        summarize_day()
                                              ▼                                    │
                                        [PostgreSQL 16]                    [외부 LLM API]
                                        6개 영역 16개 테이블 (schema.sql)   (키는 서버에만)
                                        사람·연결 / 대화 / 기억 / 놀이 / 일상 / 알림        [FCM 푸시]
```

## 설계 원칙 3개 (계획서 4.1 (2))
1. **하나의 창구, 미리 정한 약속**: 앱은 서버하고만 통신(`server/app/schemas.py`). AI는 `server/ai/contract.py` 모양으로만 주고받는다. LLM을 바꿔도 앱·서버 수정은 최소 (`server/ai/__init__.py` import 한 줄).
2. **LLM은 이해와 생성, 확정은 시스템 규칙**: LLM은 응답 문장과 기억·일상 정보의 '후보'만 만든다. 기억 저장·퀴즈 정답·질문 횟수처럼 사실이 되는 결정은 서버 규칙(`app/rules.py`)이 정한다.
3. **어르신이 동의한 것만 공유**: 보호자의 모든 조회는 매번 연결(관문 1) → 항목별 동의(관문 2) 확인 (`app/auth.py`). 동의 안 한 정보는 앱에서 가리는 게 아니라 **응답에 처음부터 없다**.

## 데이터 흐름 (계획서 그림 4-3, "점심에 국수 먹었어. 나는 트로트를 좋아해")
- **(가) 대화 → 기억 (①~⑥, 발화마다)**: 앱 STT → 서버가 발화 저장 + AI에 맥락 제공 → AI가 응답 + 기억 후보('트로트를 좋아함') + 근거 발화 → 서버가 근거가 실제 발화에 있는지, 내용이 근거와 맞는지 검사 → 통과한 것만 저장
- **(나) 기억 → 놀이 (⑦~⑬)**: 어르신이 퀴즈 제안 수락 → 서버가 기억 바탕으로 분야 고르고 **검수된 문제은행**에서 출제 → AI가 대화체로 질문 → 어르신 답 → **서버가 정답·인정 표현으로 판정** → 놀이 기록 → AI가 결과에 반응하고 다음 문제. 회상 놀이도 같은 경로
- **(다) 하루 → 가족 (⑭~⑲)**: 작별 인사 / 종료 버튼 / 30분 무응답으로 대화 끝 → AI가 일상 기록을 **항목별로 따로** 요약 (동의 안 한 항목이 섞이지 않게) → 기록 있는 항목만 저장 → 보호자 조회 시 연결·동의 확인 → 동의한 항목 요약 + 놀이 참여 횟수만

## AI 파이프라인 6단계 (계획서 4.1 (4), 곽민석)
1 입력 수신·맥락 구성 → 2 의도·맥락 분석 → 3 관련 기억 검색 → 4-A 응답 생성 / 4-B 기억 추출·일상 정보 정리 / 4-C 놀이·일상 질문 처리 → 5 결과 검증·예외 처리 (형식·유효성, 불명확 발화 재확인, 실패 시 대체 응답) → 6 결과 전달 (서버가 검증·저장)

## 데이터 보관 (계획서 4.3) — "원문은 짧게, 추출한 정보는 근거와 함께"
| 데이터 | 보관 | 어르신 | 보호자 |
|---|---|---|---|
| 대화 원문 | **30일 후 자동 삭제** | 조회 | 없음 |
| 기억 (+근거 한 문장) | 삭제 요청·탈퇴까지 | 조회·삭제 | 없음 |
| 일상 기록·요약 | 이용 기간 (근거 발화는 30일) | — | 동의한 항목 요약만 |
| 놀이 기록 | 이용 기간 | 조회 | 동의 시 참여 횟수만 |
| 퀴즈 문제은행 | 상시 (3분야×10문제, AI 초안 → 팀 검수, **검수한 것만 출제**) | — | — |
- 어르신 가입 정보는 이름만. 보호자는 로그인용 이메일. 비밀번호는 PBKDF2 해시만.
- 외부 LLM 전송은 개인정보 처리 위탁·국외 이전에 해당할 수 있음 → 식별 정보 전송 최소화 검토.

## 서버 쪽 예외 처리 (계획서 4.2)
AI 실패·형식 오류 → 대화 안 끊고 재요청, 잘못된 결과는 저장 안 함 · 근거 없는 기억 후보 → 저장 안 함 ·
일상 질문 횟수 위반 → 재요청, 그래도면 문장 수정 · 퀴즈 중 AI 실패·중단 → 서버 판정 결과로 안내, 중단은 오답 아님 ·
연결 끊김 → 발화마다 저장, 30분 무응답이면 서버가 마무리·요약 · 알림 무응답 → 반복 알림·보호자 알림 없음 ·
동의 철회·연결 해제 → 다음 조회부터 차단, 재연결 시 '공유 안 함'으로 초기화 · **중복 요청 → 요청별 고유 번호로 중복 실행 방지** ·
DB 규칙: '알림은 하루 1번', '진행 중 대화는 하나', '연결 코드는 한 번만'을 제약 조건으로도 보장
